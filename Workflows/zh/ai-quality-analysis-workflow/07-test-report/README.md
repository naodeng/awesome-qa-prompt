# 测试报告阶段 Prompt

[English](../../../en/ai-quality-analysis-workflow/07-test-report/README.md) | 简体中文

## 阶段目标

由产品、QA、UI/UX 和技术四个角色基于同一组已评审材料与可用执行证据独立分析，再汇总为一份不夸大执行状态、可追溯的测试报告。QA 负责测试覆盖、执行结果、缺陷、阻塞项和剩余风险；技术负责稳定性、性能、安全、环境和可观测性证据。产品和 UI/UX 先判断是否需要参与，只分析输入明确触发的专业范围。

## 允许输入

- 必需：测试策略、测试策略评审报告、代码评审报告、测试用例、测试用例评审报告
- 可选：测试执行报告、缺陷报告

所有输入都应提供名称、版本、来源和可读范围。执行报告与缺陷报告不是为了凑齐模板而强制生成；但两者同时缺失时，所有角色报告和汇总报告只能把执行状态写为“未执行或证据不足”，不得写“通过”“满足发布条件”或等价结论。

## 角色参与与独立边界

- QA 与技术角色固定参与，但职责不同：QA 分析用例/范围与实际执行结果，技术分析非功能、环境和可观测技术证据。
- 产品仅在输入包含业务验收、关键旅程、业务结果或产品风险证据时参与完整分析；UI/UX 仅在输入包含交互、跨端、视觉或无障碍证据时参与完整分析。
- 产品或 UI/UX 判断“不参与”时仍输出简短参与判断报告，说明依据、未覆盖范围和证据缺口；证据不足以判断时输出“待确认”。
- 四份角色 Prompt 只接收规定的上游 Artifact，不接收、读取或推测其他角色报告。
- 汇总 Prompt 只接收四份角色报告，不重新读取上游 Artifact，也不补写角色未报告的事实。

## 报告证据规则

- 已执行事实、失败、阻塞和缺陷必须引用执行记录、缺陷标识或输入中的可核查定位。
- 未执行范围与“没有证据证明已执行”必须和已执行事实分开，不能把计划覆盖写成实际覆盖。
- 数字只能来自输入，并逐项标注来源；缺少分母、统计口径或时间范围时不得计算比例或趋势。
- 缺陷报告缺失不等于零缺陷；执行报告缺失时，缺陷记录也不能证明完整执行范围。
- 发布、审批和风险接受属于 Human Task，本阶段只输出证据状态、剩余风险和建议行动。

## 推荐调用顺序

1. 锁定同一变更范围的五项必需上游 Artifact，并附上可用执行报告和缺陷报告。
2. 将相同上游输入分别交给四份角色 Prompt；不要混入其他角色输出。
3. 保留产品与 UI/UX 的参与判断报告，包括“不参与”或“待确认”结果。
4. 仅将四份角色报告交给汇总 Prompt，生成已执行事实、未执行范围、失败与阻塞、缺陷、剩余风险、证据缺口和建议行动。
5. 将汇总报告交给 Human Task 决定是否补充执行、修复、复测、接受风险或进入发布评审；AI 不代替该决定。
