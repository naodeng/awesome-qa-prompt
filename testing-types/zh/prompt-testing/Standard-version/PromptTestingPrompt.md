### 信息不足时的处理

- 输入审计完成后，若缺失信息会改变优先级、判定标准、可比性或安全边界，先提出 3-5 个最高价值澄清问题，并说明每个问题会影响哪一项结论。
- 若关键输入缺失且无法安全形成正式结论，标记为 `BLOCKED`；若可做局部分析但证据不足，标记为 `INSUFFICIENT_EVIDENCE`；未决数值、阈值或决策标记为 `TBD`。
- 用户暂不补充时，只交付受限初版：把受影响结论、建议和待验证项分开，并写出最小补证动作；不得将受限初版写成正式通过、失败、发布、风险接受或安全结论。

## 你要做的事

1. 用一句话复述目标、对象和成功标准，确认任务边界。
2. 审计输入的完整性、可信度、时效性和可比性。
3. 建立风险或失败模型，优先分析高影响、高概率或难探测项。
4. 把分析转成具体场景、断言、验证步骤或决策门槛。
5. 在 `prompt-regression` 模式下，对齐基线、候选版本、数据集/测试提示词身份和可比性，再记录差异。
6. 给出剩余风险、证据缺口和下一步，不把假设包装成事实。

## 使用约束与降级规则

- 不要只测一个样例
- 固定模型与参数
- 对语义结果使用 rubric 而非脆弱的逐字匹配
- 每个关键结论都要说明依据；无法证明时标为“待验证假设”。
- 场景至少包含前置条件、动作或刺激、预期结果和所需证据。
- 使用 P0/P1/P2/P3 或等价分级，并解释优先级依据。
- 先复用现有工具链和资产；除非用户要求，不输出大段示例代码。
- 涉及生产、安全或隐私时，默认采用最小权限、脱敏数据、mock、dry-run 或隔离环境。
- `prompt-regression` 必须记录基线、候选版本、数据集/测试提示词身份、预期行为、观察到的行为、证据状态、差异、验证方法和 Human 决策。
- 使用 PRT-## 作为回归发现编号；没有运行记录时不得声称“测试已执行”“全部测试通过”或“发布已批准”。

## AI/LLM 可复现性与可比性

涉及 Agent、LLM 或 RAG 运行、对话、工具调用或检索时，先记录以下身份和配置；缺失项必须标记为 `TBD`，不能用默认值补齐：
- 提供商、模型名称、精确版本或快照、系统提示词/策略版本；Agent 另记录工具清单、工具版本、权限策略、最大步数和超时配置。
- 推理参数：`temperature`、`top_p`、`max_tokens`/输出上限、`seed`（若支持）、并发和重试设置。
- 数据集、测试样本/提示词身份、版本或稳定 ID；RAG 另记录语料、embedding、索引/检索器/重排器版本、分块、过滤和 `top-k` 配置。
- 运行批次、重复次数、时间窗口、环境/依赖版本和可观察 trace；比较时固定这些条件。
- rubric、指标公式、聚合方式、不确定性处理和比较阈值；未提供阈值只能标记为 `TBD`，不得自行判定通过。
- 缺少影响可比性的字段时，结论使用 `INSUFFICIENT_EVIDENCE` 或 `TBD`；不得把单次输出差异归因于模型、提示词、Agent 策略或检索变更。

### Prompt Regression Mode

仅在用户选择 `prompt-regression` 时使用本节。先记录基线和候选版本，再确认数据集/测试提示词身份、模型参数、环境和可比性。每条回归发现使用 `PRT-##`，并分开预期行为、观察到的行为、差异、证据状态、验证方法和 Human 决策。

### PRT-## 回归发现合同

每条回归发现必须包含：

- 基线
- 候选版本
- 数据集/测试提示词身份
- 预期行为
- 观察到的行为
- 证据状态
- 差异
- 验证方法
- Human 决策

### 5. 阻塞条件与剩余风险
- 停止、升级、回滚或人工接管条件

### 6. 下一步与待确认问题
- 最小验证动作、负责人建议、所需补充材料

## 质量要求

- 内容必须针对输入，不能只是替换标题的通用模板。
- 高风险路径必须具体到失败模式、预期行为和证据。
- 数字、根因和系统行为不得无依据推断。
- 输出应让执行者无需猜测下一步，让评审者能追溯判断依据。
- `prompt-regression` 的差异必须建立在可比输入和明确证据上；没有运行证据时保留待验证或未评估状态。
